Версія ТЗ: 2.0  
Мова інтерфейсу: українська  
Цільова платформа: macOS  
Основний формат реалізації: один файл `main.py`  

---

## 1. Мета проєкту

Потрібно створити десктопний застосунок для macOS на Python з PyQt6: простий редактор зв'язкових схем для link analysis diagram editing.

Застосунок має дозволяти створювати вузли, з'єднувати їх зв'язками, редагувати властивості елементів, прикріплювати фото до вузлів, зберігати схему у JSON, відкривати збережені схеми, імпортувати дані з CSV та експортувати схему у PNG/PDF.

**Цільова аудиторія:** слідчі, які будують схеми взаємодій у кримінальних справах (підозрювані, їх авто, нерухомість, телефони, родичі). Користувачі — не технарі, тому інтерфейс має бути максимально простим і зрозумілим.

Інструмент призначений для внутрішнього використання, без розповсюдження.

## 9. Загальна архітектура

Основний код має бути у файлі `main.py`.

Класи:

- `Node` — модель даних вузла;
- `Link` — модель даних зв'язку;
- `NodeItem` — графічне представлення вузла на сцені;
- `LinkItem` — графічне представлення зв'язку на сцені;
- `DiagramCanvas(QGraphicsView)` — полотно з логікою взаємодії;
- `MainWindow(QMainWindow)` — головне вікно, меню, toolbar, панелі;
- `NodeDialog` — діалог створення/редагування вузла;

- `SearchDialog` або пошукова панель — пошук по вузлах;
- допоміжні `QUndoCommand` класи для Undo/Redo.

Важливо: `Node` і `Link` мають бути саме моделями даних. Графічна логіка має бути в `NodeItem` і `LinkItem`.

## 10. Модель даних Node

Клас `Node` має містити:

- `uuid` — унікальний ідентифікатор;
- `type` — тип вузла;
- `title` — назва;
- `note` — примітка;
- `date` — дата або порожнє поле;
- `x` — позиція X на полотні;
- `y` — позиція Y на полотні;
- `color` — колір рамки або акценту;
- `photo_base64` — фото або зображення, закодоване у base64 (може бути порожнім);
- `created_at` — дата створення;
- `updated_at` — дата останнього оновлення.

Вимоги:

- `uuid` генерувати через стандартний модуль `uuid`;
- координати зберігати у JSON;
- якщо колір не вказаний, використовувати колір за замовчуванням для типу вузла;
- дата може бути звичайним текстовим полем, без складної валідації;
- `photo_base64` зберігається як рядок base64 прямо у JSON — файл схеми є повністю самодостатнім і не потребує зовнішніх файлів зображень;
- підтримувані формати фото: JPG, PNG, BMP, GIF;
- якщо `photo_base64` задано, `NodeItem` відображає мініатюру фото замість іконки типу.

---

## 11. Модель даних Link

Клас `Link` має містити:

- `uuid` — унікальний ідентифікатор;
- `source_uuid` — UUID першого вузла;
- `target_uuid` — UUID другого вузла;
- `label` — підпис зв'язку;
- `line_type` — тип лінії;
- `direction` — напрямок;
- `note` — примітка;
- `created_at` — дата створення;
- `updated_at` — дата останнього оновлення.

Вимоги:

- зв'язок не має існувати без двох валідних вузлів;
- при відкритті JSON пошкоджені зв'язки треба пропускати з попередженням;
- підпис зв'язку має відображатися по центру лінії.

## 13. NodeItem

`NodeItem` має:

- якщо `photo_base64` задано — відображати мініатюру фото у верхній частині вузла;
- якщо фото немає — відображати іконку типу;
- відображати назву;
- відображати тип;
- мати кольорову рамку;
- підтримувати виділення;
- підтримувати drag & drop;
- підтримувати подвійний клік для редагування;
- підтримувати контекстне меню;
- при переміщенні оновлювати координати у відповідному `Node`;
- при переміщенні автоматично оновлювати всі пов'язані `LinkItem`.

Контекстне меню вузла:

- Редагувати;
- Видалити;
- Змінити колір;
- Дублювати.

---

## 14. LinkItem

`LinkItem` має:

- відображати лінію між двома `NodeItem`;
- відображати підпис по центру;
- підтримувати вибір кліком;
- підтримувати подвійний клік для редагування;
- підтримувати контекстне меню;
- оновлювати геометрію при русі пов'язаних вузлів.

Типи ліній:

- `solid_arrow` — суцільна лінія зі стрілкою;
- `dashed` — пунктирна лінія;
- `double` — подвійна лінія;
- `bidirectional` — двостороння стрілка.

Напрямки:

- `none` — без стрілки;
- `source_to_target` — від першого вузла до другого;
- `target_to_source` — від другого вузла до першого;
- `bidirectional` — двосторонній зв'язок.

## 16. Режими роботи полотна

Потрібно реалізувати мінімум два режими:

### Select Tool

Режим за замовчуванням.

Має дозволяти:

- вибирати вузли;
- вибирати зв'язки;
- переміщати вузли;
- використовувати контекстні меню;
- редагувати елементи подвійним кліком.

### Link Tool

Режим створення зв'язків.

Логіка:

1. Користувач натискає кнопку `Link Tool`.
2. У статусбарі показується: `Link Tool: виберіть перший вузол`.
3. Користувач клікає перший вузол.
4. У статусбарі показується: `Link Tool: виберіть другий вузол`.
5. Користувач клікає другий вузол.
6. Відкривається діалог створення зв'язку.
7. Після підтвердження створюється `Link` і `LinkItem`.
8. Новий зв'язок стає виділеним.

`Esc` має скасовувати поточне створення зв'язку.

## 21. Видалення

Видалення має працювати:

- через клавішу `Delete`;

## 22. Дублювання

- змістити позицію на 30-50 px;
- не копіювати зв'язки автоматично;

## 27. Undo/Redo

Використати `QUndoStack`.

Потрібно підтримати Undo/Redo для:

- додавання вузла;
- видалення вузла;
- редагування вузла;
- зміни кольору вузла;
- дублювання вузла;
- додавання зв'язку;
- видалення зв'язку;
- редагування зв'язку.

Бажано підтримати Undo/Redo для:

- переміщення вузла.

Якщо повна підтримка Undo/Redo для переміщення складна, треба:

- реалізувати стабільний базовий Undo/Redo для створення, видалення та редагування;
- структурувати код так, щоб команду переміщення можна було додати пізніше;
- не ламати drag & drop заради Undo/Redo переміщення.

## 28. Збереження JSON

Формат збереження: JSON.

JSON має містити:

- `schema_version`;
- `nodes` (включно з полем `photo_base64` для кожного вузла);
- `links`;
- `viewport`;
- `grid_enabled`;
- `created_at`;
- `updated_at`.

**Важливо:** файл схеми є повністю самодостатнім — всі фото зберігаються як base64-рядки всередині JSON. Ніяких зовнішніх файлів зображень не потрібно. Один файл = вся схема.

Приклад:

```json
{
  "schema_version": 1,
  "nodes": [
    {
      "uuid": "...",
      "type": "Person",
      "title": "Іванов І.І.",
      "note": "",
      "date": "",
      "x": 100,
      "y": 150,
      "color": "#4A90D9",
      "photo_base64": "iVBORw0KGgoAAAANSUhEUgAA...",
      "created_at": "2026-05-18T12:00:00",
      "updated_at": "2026-05-18T12:00:00"
    }
  ],
  "links": [],
  "viewport": {
    "center_x": 0,
    "center_y": 0,
    "zoom": 1.0
  },
  "grid_enabled": true,
  "created_at": "2026-05-18T12:00:00",
  "updated_at": "2026-05-18T12:30:00"
}
```

Вимоги:

- `Save` зберігає у поточний файл;
- якщо шлях ще не заданий, `Save` відкриває `Save As`;
- `Save As` відкриває `QFileDialog`;
- після успішного збереження документ перестає вважатися зміненим;
- у статусбарі показується `Файл збережено`.

---

## 29. Відкриття JSON

При відкритті JSON потрібно:

1. Перевірити, що файл читається.
2. Перевірити, що JSON валідний.
3. Перевірити `schema_version`.
4. Очистити поточну сцену.
5. Створити всі вузли.
6. Створити всі валідні зв'язки.
7. Пропустити пошкоджені зв'язки.
8. Показати попередження, якщо частина зв'язків була пропущена.

Застосунок не має падати при неправильному JSON.

## 32. Експорт PDF

PDF-експорт є **обов'язковим** — слідчі використовують схеми як офіційні документи у справах і потребують друку високої якості.

Вимоги:

- використовувати `QPrinter` або інший стабільний механізм PyQt6;
- експортувати всю сцену у PDF;
- якість має бути достатньою для друку на папір формату A4;
- якщо PDF не вдалося реалізувати стабільно, застосунок не має падати;
- у такому випадку показати зрозуміле повідомлення: `Експорт PDF поки недоступний` і запропонувати альтернативу — експорт PNG.

## 34. CSV Import

- `type`;
- `title`;
- `note`;

- `x`;

### links.csv

Колонки:

- `source_id`;

Логіка:

- після імпорту показати повідомлення з кількістю імпортованих вузлів і зв'язків;

## 43. Acceptance Criteria

Перед здачею потрібно перевірити такі сценарії:

17. Можна експортувати PNG.
18. Можна експортувати PDF.
19. `Cmd+S` викликає Save.

## 44. Самоперевірка ТЗ

Це ТЗ перевірене на такі потенційні суперечності:

- Вимога `один файл main.py` збережена: архітектура описана класами всередині одного файлу, без обов'язкового рознесення на модулі.
- `Node` і `Link` не змішані з графікою: для сцени окремо вказані `NodeItem` і `LinkItem`.
- MVP відділений від optional-функцій: PNG, PDF, JSON (з фото), вузли, зв'язки і базовий Undo/Redo є обов'язковими; мінімапа — best effort.
- Фото зберігаються як base64 всередині JSON — файл самодостатній, жодних зовнішніх залежностей.
- IBM i2 згадується лише як заборона копіювання бренду та UI, а не як джерело для відтворення.
- Приватність врахована: локальна робота без мережі, телеметрії та зовнішніх API.
- JSON має `schema_version`, UUID для вузлів і зв'язків, а також базову інформацію про viewport.
- Вказано, що лінії мають оновлюватися при переміщенні вузлів.
- Вказано, як діяти при пошкоджених JSON/CSV, щоб застосунок не падав.
- Розгортання описано: `.app` через PyInstaller для нетехнічних користувачів.
